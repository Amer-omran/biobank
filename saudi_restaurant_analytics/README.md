# منصة ذكاء اصطناعي لتحليل مشاعر العملاء وسلوك تفضيل الوجبات في المطاعم السعودية

**Saudi Restaurant Sentiment & Food Preference Analytics Platform**

منصة ويب عربية (من اليمين لليسار) تحلل مراجعات المطاعم والتعليقات العربية — الفصحى واللهجة السعودية —
لاستخراج الشعور العام، والمشاعر حسب جوانب الرأي، والوجبات المذكورة، ثم تعرض النتائج في لوحة تحكم
تفاعلية وتنشئ تقارير Excel وPDF. تعمل محليًا على جهازك بالكامل دون خدمات سحابية أو مفاتيح مدفوعة.

> ⚠️ **تنبيه مهم:** المنصة تحتوي على **بيانات تجريبية اصطناعية** مولدة آليًا لتجربة الواجهة. أسماء
> المطاعم فيها خيالية (تنتهي بكلمة «تجريبي»)، ونتائجها **ليست نتائج بحثية فعلية**.

## التثبيت خطوة بخطوة

### 1) ثبّت Python

تحتاج **Python 3.10 أو أحدث** (اختُبر المشروع على Python 3.13).

- **ويندوز:** نزّل Python من الموقع الرسمي python.org، وعند التثبيت **فعّل خيار «Add Python to PATH»**.
- **ماك:** نزّله من python.org أو عبر `brew install python`.
- **لينكس:** غالبًا مثبت مسبقًا.

للتأكد، افتح الطرفية (Terminal، أو «موجه الأوامر» في ويندوز) واكتب:

```bash
python --version
```

> في ماك ولينكس قد يكون الأمر `python3` بدل `python`، و`pip3` بدل `pip`.

### 2) انتقل إلى مجلد المشروع

```bash
cd saudi_restaurant_analytics
```

### 3) أنشئ بيئة افتراضية (موصى به)

البيئة الافتراضية تعزل مكتبات المشروع عن بقية جهازك:

```bash
python -m venv .venv
```

ثم فعّلها — **ويندوز:**

```bash
.venv\Scripts\activate
```

**ماك/لينكس:**

```bash
source .venv/bin/activate
```

ستظهر `(.venv)` في بداية سطر الأوامر؛ هذا يعني أنها مفعلة.

### 4) ثبّت المكتبات

```bash
pip install -r requirements.txt
```

قد يستغرق ذلك بضع دقائق في المرة الأولى.

## طريقة الاستخدام

### التجربة السريعة (دقيقة واحدة)

1. افتح **الرئيسية** واضغط **«تحميل البيانات التجريبية وتحليلها»**.
2. تنقّل بين الصفحات من القائمة الجانبية.

### مع بياناتك الحقيقية

1. **استيراد البيانات:** ارفع ملف CSV أو Excel. ستظهر معاينة، ثم **اختر بنفسك** عمود التعليقات
   (إلزامي)، وعمود المطعم والتاريخ والتقييم والمدينة والوسم (اختيارية). المنصة تقترح أعمدة
   تلقائيًا لكنها لا تفترضها. سيظهر تقرير تحقق (صفوف فارغة، مكررة، تواريخ أو تقييمات غير صالحة).
2. **تحليل المشاعر:** اختر مجموعة البيانات والمحرك ثم اضغط «تشغيل التحليل». يمكنك أيضًا تجربة تعليق
   واحد في المربع أعلى الصفحة.
3. **تحليل الوجبات:** الوجبات الأكثر ذكرًا وتوزيع المشاعر لكل وجبة والبحث عن وجبة معينة.
4. **مقارنة المطاعم:** اختر مطعمين أو أكثر. لن يُرتب أي مطعم لديه أقل من 20 تعليقًا (قابل للتعديل).
5. **التقارير:** اختر المطعم والفترة، ثم نزّل Excel أو PDF أو CSV.
6. **النموذج والتقييم:** درّب نموذج Scikit-learn إذا كانت لديك بيانات موسومة.
7. **قاموس الوجبات:** أضف وجبات أو مرادفات أو اختلافات إملائية واحفظ.

ملف تجريبي جاهز لتجربة صفحة الاستيراد: `data/sample/demo_reviews_synthetic.csv`
(يمكن إعادة توليده بالأمر `python scripts/generate_demo_data.py`).

## كيف يعمل التحليل؟ (شرح مبسط)

### معالجة النص (`sra/text_processing.py`)

- حذف الروابط والفراغات الزائدة، والتعامل مع القيم الفارغة.
- **النص الأصلي يُحفظ كما هو**، مع إخفاء أرقام الجوال والبريد وأسماء الحسابات فقط (حماية للخصوصية).
- **تطبيع محدود وقابل للتعديل** للمطابقة فقط: (أ إ آ ← ا)، (ى ← ي)، (ة ← ه)، حذف التشكيل والتطويل،
  وتقصير التكرار (حلوووو ← حلوو). كل خيار يمكن تعطيله من `NormalizationOptions`.
- **لا تُحذف كلمات النفي** (لا، ما، مو، مب، مش، ليس، غير، بدون) ولا الرموز التعبيرية ولا علامات التعجب.
- كشف التعليقات المكررة رغم اختلاف التشكيل والفراغات.

### محلل المشاعر حسب الجوانب (`sra/sentiment.py` + `sra/lexicon.py`)

المحلل الأساسي **قائم على القواعد والقاموس**، فلا يحتاج تدريبًا ولا إنترنت، وكل حكم فيه قابل للتفسير:

1. يقسم التعليق إلى مقاطع عند الترقيم وأدوات الاستدراك («بس»، «لكن»).
2. يحدد كلمات الجوانب (الأكل، السعر، المندوب...) وأسماء الوجبات.
3. يحدد كلمات الرأي (لذيذ، غالي، زفت، رهيب...) مع:
   - **النفي:** «مو حلو» سلبي، «ماعجبني» سلبي، و«مو سيء» إيجابي ضعيف (وليس ممتازًا).
   - **التكثيف:** «لذيذ مرة»، «حلوووو».
   - **الانعدام:** «مافي نظافة» ← سلبي للنظافة.
   - **التعابير:** «ما شاء الله»، «ما قصروا»، «ماله طعم»، «يستاهل كل ريال».
   - **الكلمات المشروطة:** «كبير» إيجابية مع الكمية وسلبية مع السعر.
4. يربط كل رأي بأقرب جانب في المقطع نفسه، أو بجانبه الضمني («غالي» ← السعر). الجوانب المتتالية
   تشترك في الرأي: «الأكل والخدمة ممتازين».
5. يحسب الشعور العام. المقطع الذي يلي «بس/لكن» يُعطى وزنًا أكبر.

**درجة الثقة** تقديرية تعتمد على قوة الإشارات ووضوحها، وليست احتمالًا معايرًا إحصائيًا. إذا قلّت عن
60% تظهر النتيجة **«غير مؤكد»**، وإذا لم توجد أي كلمة رأي فالنتيجة «محايد — غير مؤكد» بدل حكم قطعي.

لتوسيع القاموس: أضف كلمات إلى `POSITIVE_WORDS` أو `NEGATIVE_WORDS` في `sra/lexicon.py` بأي إملاء.

### استخراج الوجبات (`sra/dishes.py`)

- القاموس في `data/dishes_dictionary.csv` (أو من صفحة «قاموس الوجبات»): الاسم الموحد، الفئة، المرادفات مفصولة بـ `|`.
- يدعم السوابق (بالكبسة، والمندي)، والتطويل (شاورماااا)، والعبارات المركبة (دجاج مقلي، قهوة سعودية).
- **لا يستخرج إلا ما في القاموس**، فلا يمكن أن يخترع وجبة.
- تُربط الوجبة بالجانب والشعور فقط عند ورودهما في **المقطع نفسه** (دليل نصي كافٍ).

### نموذج Scikit-learn (`sra/ml_model.py`)

TF-IDF على مقاطع الحروف والكلمات مع انحدار لوجستي. يحتاج وسومًا: عمود وسم في بياناتك (الأفضل)، أو
وسوم مشتقة من التقييم الرقمي (1-2 سلبي، 3 محايد، 4-5 إيجابي — تقريبية). تُقسم البيانات 80/20 وتُعرض
الدقة وMacro-F1 ومصفوفة الالتباس **على بيانات الاختبار فقط**. من سطر الأوامر:

```bash
python scripts/train_model.py --from-ratings
```

> النموذج المدرب على البيانات التجريبية سيُظهر دقة مرتفعة بشكل مضلل لأنها مولدة من قوالب محدودة.

## مجموعة بيانات AQTE على Hugging Face

طُلب البدء باستكشاف المجموعة `bayandashnan/AQTE-Arabic-Quote-Triplet-Extraction`.
**تعذّر الوصول إليها من بيئة التطوير** (موقع huggingface.co محجوب فيها، ولم يُعثر على وصف منشور لها
في البحث)، لذلك **لم نفترض أسماء أعمدتها أو وسومها** في الكود. بدلًا من ذلك:

1. ثبّت المكتبات الاختيارية: `pip install -r requirements-optional.txt`
2. شغّل سكربت الاستكشاف على جهازك:

   ```bash
   python scripts/explore_hf_dataset.py
   ```

   يطبع الأقسام وعدد الصفوف، وكل عمود مع نوعه وأمثلة منه ونسبة النص العربي، والقيم المتكررة،
   وأسماء الوسوم إن كانت من نوع ClassLabel. الأعمدة المتداخلة (قوائم triplets مثلًا) تتحول إلى JSON نصي.
   ويحفظ كل قسم في `data/hf_export/` مع ملف `profile.json`.
3. **تحقق بنفسك** أن المحتوى مراجعات مطاعم مناسبة (اسم المجموعة يشير إلى «اقتباسات» و«ثلاثيات»، وقد
   لا تكون مراجعات مطاعم أصلًا).
4. ارفع ملف CSV الناتج من صفحة «استيراد البيانات» واختر الأعمدة المناسبة يدويًا.

**طريقة بديلة دون مكتبات إضافية:** افتح صفحة المجموعة على huggingface.co، وراجع الأعمدة في عارض
البيانات (Dataset Viewer)، ثم نزّل ملف البيانات من تبويب «Files and versions» (غالبًا بصيغة
`.parquet` أو `.json` أو `.csv`) وارفعه مباشرة في صفحة «استيراد البيانات»، فالمنصة تقرأ هذه الصيغ.

### التقييم على AQTE

بعد فحص المجموعة تبيّن أنها **14,783 مراجعة حقيقية لـ 774 مطعمًا في السعودية** من Google Maps،
وكل مراجعة فيها قائمة آراء: `{"aspect": "الطعام", "avg_sentiment": 1, "quotes": "حلو الاكل"}`
(29 فئة جوانب، و3 أقطاب)، مع عمود `rate` من 1 إلى 5. الرخصة CC BY 4.0، فاذكر المجموعة في مراجعك.

نزّل `train_split.json` و`test_split.json` من تبويب «Files and versions»، ثم:

```bash
python scripts/prepare_aqte.py test_split.json
```
يُنشئ `test_split_platform.csv` للاستيراد في المنصة، مع عمود `gold_label` (الشعور المشتق من آراء AQTE)
لتختاره في خانة «عمود الوسم».

```bash
python scripts/evaluate_aqte.py test_split.json --train train_split.json
```
يقيّم الشعور العام (القاموس مقابل Scikit-learn)، واكتشاف كل جانب (Precision وRecall وF1)، ودقة
شعور الجوانب، ويحفظ النتائج في `data/aqte_evaluation.xlsx`. ربط فئات AQTE الـ 29 بجوانب المنصة
السبعة موجود في `ASPECT_MAP` داخل `sra/aqte.py`، وهو قرار منهجي اذكره في التقرير.

لتحسين القاموس، حلّل الأخطاء على **ملف التدريب فقط**:

```bash
python scripts/error_analysis_aqte.py train_split.json --limit 2000
```
يحفظ `data/aqte_error_analysis.xlsx` بالجوانب الفائتة مع عباراتها، وأخطاء الشعور، وكلمات متكررة
في العبارات الفائتة غير موجودة في القاموس (راجعها قبل إضافتها). الطباعة في موجه الأوامر بالإنجليزية
لأن موجه أوامر ويندوز لا يعرض العربية غالبًا؛ التفاصيل العربية في ملفات Excel.

## نموذج Hugging Face الاختياري

- النموذج المقترح: `CAMeL-Lab/bert-base-arabic-camelbert-da-sentiment` (CAMeLBERT مضبوط لتصنيف
  مشاعر اللهجات العربية). **لم نتمكن من فتح بطاقته من بيئة التطوير**، فراجعها بنفسك قبل الاعتماد عليه:
  بيانات التدريب ومجالها (غالبًا تغريدات عامة وليست مراجعات مطاعم)، أسماء الوسوم، الرخصة، والقيود.
- المنصة **تقرأ أسماء الوسوم من إعدادات النموذج** وترفضه إن لم تكن وسومه قابلة للربط بوضوح بإيجابي/سلبي/محايد.
- للتثبيت: `pip install -r requirements-optional.txt` (حجم كبير). لتغيير النموذج عرّف متغير البيئة `SRA_TRANSFORMER_MODEL`.
- النموذج يحدد الشعور العام فقط؛ الجوانب والوجبات تبقى من محلل القاموس. إن لم يُثبّت، تعمل بقية المنصة طبيعيًا.

## بيانات وسائل التواصل الاجتماعي

- **الطريقة الموصى بها:** صدّر البيانات من الأداة الرسمية للمنصة ثم استوردها كملف CSV.
- **موصل X API v2** (`sra/connectors.py`): يستخدم نقطة البحث الحديث الرسمية فقط، ويحتاج مفتاحًا في متغير
  البيئة `X_BEARER_TOKEN` وفئة اشتراك تسمح بالبحث. لا يحفظ أسماء الحسابات أو معرفاتها.
- **لا يوجد أي كشط لصفحات الويب** أو تجاوز لشروط المنصات أو حدود الاستخدام. تأكد أن شروط اشتراكك تسمح
  بتخزين المحتوى لأغراض بحثية.
- **لا تكتب أي مفتاح داخل الكود.** عرّفه في الطرفية قبل التشغيل — ويندوز:

  ```bash
  set X_BEARER_TOKEN=المفتاح_هنا
  ```

  ماك/لينكس:

  ```bash
  export X_BEARER_TOKEN=المفتاح_هنا
  ```

## قاعدة البيانات

SQLite في `data/restaurant_analytics.db` (يمكن تغيير المسار بمتغير البيئة `SRA_DB_PATH`).

| الجدول | المحتوى |
|---|---|
| `datasets` | مجموعات البيانات ونوعها، وهل هي اصطناعية |
| `reviews` | النص الأصلي والمنظف، المصدر، التاريخ، المطعم، المدينة، التقييم الأصلي، الوسم الأصلي |
| `analyses` | الشعور، درجة الثقة، مختلط/غير مؤكد، اسم النموذج وإصداره، تاريخ التحليل |
| `aspects` | الجانب، شعوره، درجته، العبارة الداعمة، والوجبة المرتبطة |
| `dishes` | الاسم الموحد للوجبة، الفئة، المرادفات |
| `review_dishes` | ربط كل تحليل بالوجبات المذكورة وشعورها (متعدد-لمتعدد) |

- مفاتيح أساسية وخارجية مع `ON DELETE CASCADE` (حذف مجموعة يحذف تعليقاتها وتحليلاتها).
- قيود `CHECK` على القيم المسموحة، وفهرس فريد يمنع تكرار التعليق نفسه (النص + المطعم + التاريخ).
- إعادة التحليل بالإصدار نفسه تستبدل النتيجة، وبإصدار جديد تُحفظ بجانب القديمة للمقارنة.
- الصفحة الرئيسية تعرض فحص سلامة العلاقات (`PRAGMA foreign_key_check`).
- لا تُخزن أسماء المستخدمين أو معرفاتهم.

قيود قاعدة البيانات والحذف المتسلسل، الاستيراد بترميزات مختلفة، التحليلات والترتيب، النماذج، التقارير
(Excel وPDF)، موصل API (بطلبات وهمية دون إنترنت)، وتشغيل كل صفحات الواجهة دون أخطاء.

الاختبارات تستخدم قاعدة بيانات مؤقتة ولا تلمس بياناتك.

## حدود المنصة وتنبيهات منهجية

- التحليل الآلي قد يخطئ في **السخرية** («يا سلام على السرعة» بعد ساعة انتظار) والعامية غير الموجودة في القاموس.
- **عدد مرات ذكر الوجبة مؤشر تفضيل مستنتج من التعليقات، وليس عدد مرات الشراء.** لا يصح استنتاج
  المبيعات إلا من بيانات شراء مستقلة.
- مقارنة المدن تعكس المطاعم الموجودة في بياناتك فقط، ولا تمثل المدينة كلها.
- الترتيب يعتمد على الحد الأدنى لفترة ثقة ويلسون 95%، والفروق بين فترات متداخلة قد لا تكون حقيقية.
- للبحث العلمي: قيّم المحلل على **عينة موسومة بشريًا من بياناتك** (صفحة «النموذج والتقييم» ← «مقارنة
  بالوسوم الأصلية»)، وأبلغ عن الدقة الفعلية بدل الاعتماد على الأرقام التجريبية.

## حل المشكلات الشائعة

| المشكلة | الحل |
|---|---|
| `streamlit: command not found` | فعّل البيئة الافتراضية، أو شغّل `python -m streamlit run app.py` |
| الحروف العربية في CSV تظهر رموزًا غريبة | المنصة تجرب UTF-8 وcp1256 تلقائيًا؛ إن استمرت المشكلة احفظ الملف من Excel بصيغة «CSV UTF-8» |
| «لا يوجد نموذج مدرب بعد» | درّب النموذج من صفحة «النموذج والتقييم» أو استخدم محرك القاموس |
| أريد البدء من جديد | أغلق المنصة واحذف الملف `data/restaurant_analytics.db` |
| تعديل القاموس لم يظهر في النتائج | أعد التحليل مع إلغاء خيار «غير المحللة فقط» |
